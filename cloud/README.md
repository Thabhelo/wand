# Wand hosted relay

Cloudflare Workers at https://api.getwand.app, D1 `wand-registry` and one SQLite Durable Object per device. Firebase Authentication project `wand-getwand` provides user sign-in. The deployment uses the providers' free tiers, which have quotas. See [current build status](../docs/BUILD_STATUS.md) for release and integration progress.

Use Node 22/24 LTS. Run `npm ci`, `npm run build:contracts`, `npm test`. Validators compile from `../contracts/v1.schema.json` before deployment. Tests use isolated Workers bindings, never a production auth bypass.

## Two separate permissions

The dashboard uses Firebase sign-in with Google or with an email and password, with Facebook hidden from public sign-in while Meta verification is deferred. Its ID tokens must have the project-specific issuer/audience, an approved Google/Facebook sign-in provider, valid signature and timestamps; Google also requires a verified email claim. With `PASSWORD_ENABLED` set to `true`, password tokens are accepted too, but only with a verified email; an unverified one gets `email_not_verified` (403) on every account endpoint. `/config` reports `passwordEnabled` so the dashboard shows its email form. See [email and password accounts](../docs/FIREBASE_CONNECTIONS.md#email-and-password-accounts). Facebook identity is the Firebase UID, never an email-based ownership lookup. The app connects a device to this same account through the existing browser pairing ceremony; it never stores the Google token. Only device credentials are stored in Keychain.

The assistant uses Wand's separate OAuth authorization server, built with `@cloudflare/workers-oauth-provider`. Firebase ID tokens are not accepted at `/connector/*`; connector tokens are not accepted at dashboard administration endpoints. `/authorize` requires a registered client on `MUSE_CLIENT_IDS`, an exact registered callback, S256 PKCE, state, resource `https://api.getwand.app/connector`, and action scopes `wand:<catalog_action>`. No public dynamic client registration or client-metadata URL fetching is enabled.

Consent requires an authenticated user, explicitly chosen devices/actions and an Allow click. High-risk actions are unchecked initially. Consent requests expire after ten minutes, bind to the first authenticated reviewer and are single-use. Tokens last 15 minutes, refresh grants 30 days. Each command checks the D1 connection record, permitted device, permitted action and current ownership. Narrowed token scopes cannot widen the original grant. Revoking a connection blocks issued tokens immediately through D1 and purges available OAuth grants from KV. Account deletion installs a deletion barrier, revokes OAuth grants, deletes connection records, revokes all device tokens, closes sockets and purges device data.

Firebase user-session revocation is subject to Firebase ID-token expiry (up to one hour); this verifier does not contact Firebase Admin on every request. Account/device/connector revocation in Wand is checked on the relay. KV propagation can delay physical OAuth-record deletion; D1 revocation remains authoritative. An action already dispatched cannot be recalled.

## Deployment

Muse portal verification (November 9): `npm run deploy` publishes the configured, expiring plain-text host challenge. `node scripts/update-muse-callbacks.mjs` previews the exact callback additions to the existing client; `--apply` writes them to production KV while retaining its previous callbacks and other properties. Run only with authorized Cloudflare credentials. The portal's sign-in test also needs `https://api.getwand.app/authorize?resource=https%3A%2F%2Fapi.getwand.app%2Fconnector` as its Authorization URL because it does not add the required resource parameter itself. The token endpoint remains `https://api.getwand.app/oauth/token`. Do not relax PKCE, callback matching or resource binding to pass a test. Verify both the public challenge and native sign-in after deployment; source changes alone do not establish production success.

`npm exec wrangler -- d1 migrations apply wand-registry --remote`, then `npm run deploy`. Set public `FIREBASE_*` web configuration in wrangler.jsonc. Firebase authorized domains include app.getwand.app and getwand.app. The website proxies account API calls to this relay. Website deployment copies canonical dashboard files from `../web`.

Wand's separate connector OAuth service is implemented and tested with a fake client. The Muse application has been submitted. `node scripts/register-client.mjs "<name>" "<exact https callback>" --apply` writes one public PKCE client to production KV; `MUSE_CLIENT_IDS` lists the one registered for Muse. Muse authorized natively through that client on October 5; see [reviewer account and Muse client](../docs/FIREBASE_CONNECTIONS.md#reviewer-account-and-muse-client). Muse has used Wand through the web controls; that does not establish a native connector connection. Public discovery: https://api.getwand.app/openapi.json and https://api.getwand.app/.well-known/oauth-authorization-server.

See [the transport contract](../contracts/TRANSPORT.md) for device routing. No offline queue or reconnect replay. Cloud command/audit records contain no raw params or state. Device alarms purge commands/audits after 90 days; the [registry alarm](../docs/REGISTRY_CLEANUP.md) expires pairing and consent records hourly. Restoring provider backups needs deletion replay before service resumes. The signed, notarized Mac release is available from [the download page](https://getwand.app/download/); [release evidence](../docs/RELEASE_0_13_1.md) records what was tested and what remains open.

## Offline emails

When a paired Mac has been offline for more than six hours, its owner gets one email per outage so a Mac that quit Wand in another country does not stay unreachable unnoticed. The Device object records `offline_since` the moment its authenticated socket goes away (heartbeat timeout, socket close or `bye`) and folds `offline_since + 6 h` into the same `schedule()` deadline set that drives heartbeat and command timeouts. When that alarm fires and the Mac is still offline, not revoked, its owner is not deleting their account and this outage has not been reported yet, the relay looks up the owner's address in D1 `users`, sends through `src/notify.js` and marks the episode notified. A reconnect clears the episode, so the next outage is reported again; revoked, purged and unclaimed devices never produce mail, and a provider error is retried every 15 minutes at most three times. Owners whose address is not stored yet get nothing until they next open the dashboard, which upserts `users` from the Firebase token at no extra read (the row piggybacks on the deletion-barrier query and is written only when the address changes). Account deletion removes the row.

Subject: `Wand on <device name> has been offline since <time UTC>`. The body gives the last-seen time in UTC with a relative phrase, says commands from the phone or Muse will fail until Wand is opened on that Mac, says it is sent once per outage, and ends with "You receive this because <email> owns this Mac in Wand. Disconnect the Mac at https://app.getwand.app to stop these." Logs carry event names only, never addresses or device names.

Sending uses the Workers `send_email` binding `EMAIL` with the `MAIL_FROM` var (display name "Wand", default `wand@getwand.app`). If the binding or the sender is missing the relay logs `offline_email_skipped` and carries on, so deploying without email configured is safe; setting `MAIL_FROM` to an empty string disables sending the same way, and any other address on the enabled domain changes the sender. Email Sending must be enabled once on the zone by the account owner with `npx wrangler email sending enable getwand.app`; nothing in this repository runs that command, and it is the only step that touches the domain (it sets up the sending DNS records on the zone; `npx wrangler email sending dns get getwand.app` shows them). Until that is done, and on the Workers Free plan in general, Cloudflare delivers only to the account's verified destination addresses, so other owners' notices are dropped by the provider rather than by this code. Migration `0003_users.sql` must be applied before deploying this version.

## Database read costs

The `commands_pending` partial index includes only dispatched and delivered commands. Heartbeat scheduling, timeouts and reconnect handling use it to skip completed history. Existing device databases create the index when their object next starts; no records are removed, and the 90-day retention period stays unchanged.

`tests/device-storage.test.js` measures actual Workers SQLite `rowsRead` with 5,000 completed commands. It also checks index creation after an existing object restarts, timeout handling and generation fencing. Keep these checks when changing the command queries: an unindexed status filter can scan the whole history on every heartbeat.

Verified September 24, 2026: all 55 cloud tests passed. The scheduling regression read **2 rows with the index versus 5,002 without it**. Production version `73d2e9d6-34c0-4837-b6f6-1d56797d7054` deployed at 18:27 UTC, and a real Mac status command succeeded afterward. Cloudflare's first complete idle minute afterward reported 22 device-namespace reads, versus 2,592–3,888 per minute before deployment. This is an initial live observation, not a full-day usage guarantee; reads already consumed still count until the daily reset.

## Facebook activation
The browser adapter supports Facebook sign-in and explicit linking from an existing signed-in account. Configure a dedicated Meta Facebook Login app, register `https://wand-getwand.firebaseapp.com/__/auth/handler` as its exact redirect, and save its app ID/secret in Firebase Authentication (not in this repository). After verification, set FACEBOOK_ENABLED to true and deploy. No email-based account merging occurs in Wand. Facebook linking and sign-in were verified for the developer account on 2026-09-20. FACEBOOK_ENABLED is now false to keep public onboarding Google-only. The Firebase provider is retained for existing linked accounts; Meta verification is not on the release critical path.
